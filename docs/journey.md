# How we got here
*Created: 2026-11-04. Last updated: 2026-11-04.*

These are the real problems we hit while building Unfenced, in the order we hit them, and what we changed. Days one to four (27 to 30 October) were built in the public ascent-learning-agents repo and moved here as the first commit on 31 October; everything after that is in this repo's history, 380 commits between 31 October and 4 November.

Each entry gives the problem, what caused it, the fix, the commits (short shas; `git show <sha>` opens one) and the review or red team reports in [reviews/](../reviews/). Most risky work went through a reviewer and a red team, up to three rounds each. A "FIX FIRST" verdict meant the branch could not merge until the findings were fixed. Decision numbers point to [decisions.md](decisions.md). What is still open is listed at the end and in [known-limits.md](known-limits.md).

The demo store is Beyond the Limits. Its name is made up; its products and prices are real, and the practice customers are built from a real shop's chats with names, numbers and addresses removed.

## 31 October: the first build and the first Arena runs

**The base.** The Arena, Reflection and the Sales agent on Beyond the Limits went in as the first commit (`249a588`). The eval gate reports each lesson as cases fixed and cases broken, with a McNemar check on the two counts (`e444a9a`, decision 27).

**An early Arena run found three wrong failures.** The delivery fact check read an exchange window ("you can exchange within 14 days") as a delivery time. The name printing price failed when a boot was named beside it. No tool gave product photo links, and the agent handed off photo requests. Fix: the nearest delivery or exchange word decides, printing counts as an extra on any boot, and the store tool gives each product's image link; the send check refuses any link the tool did not give (`54674a0`).

**The fast note guard let promises and policy through.** A fast note is a one line "try this instead" for the next chat. The red team got promises and policy past the guard (round 1, finding 1, confirmed medium). In round 2 every encoding trick was refused, but 48 of 89 paraphrased promises still passed. Fix: the guard's banned list is built from the plug's whole high risk list plus payment, personal data, policy and number words in Arabic and Franco, and every line break counts as a new line (`5d9b203`). Reports: [review r1](../reviews/2026-10-31/review-unfenced-risky-1031-r1.md), [r2](../reviews/2026-10-31/review-unfenced-risky-1031-r2.md), [r3](../reviews/2026-10-31/review-unfenced-risky-1031-r3.md) (PASS); [red team r1](../reviews/2026-10-31/redteam-unfenced-risky-1031-r1.md), [r2](../reviews/2026-10-31/redteam-unfenced-risky-1031-r2.md), [r3](../reviews/2026-10-31/redteam-unfenced-risky-1031-r3.md).

**An agent that lied could still win.** A match counted as won when the customer said yes, even if no order was placed. Fix: a match is won only when draft_order really placed the order after the yes, and "order confirmed" with no order fails the fact check (decision 26).

**The price check was too loose, then too strict.** Each fix round on the price check moved the problem. Round 2 of the red team found that new spellings of a boot-first price got through after the round 1 lines were blocked. Fixes went in clause by clause: an add-on's price is read only for the extra its clause names, and a boot clause may give the extra's price right after (`3024feb`, `cd2da14`, `61aff16`, `d7730fc`, `29eaee5`). Round 3 reran all 13 earlier price lines and every one was blocked. Each review round still ended FIX FIRST, the last on one regression, so the shapes it still misses are written down in known-limits.md. Reports: [review r1](../reviews/2026-10-31/review-unfenced-gatefb-1031-r1.md), [r2](../reviews/2026-10-31/review-unfenced-gatefb-1031-r2.md), [r3](../reviews/2026-10-31/review-unfenced-gatefb-1031-r3.md); [red team r1](../reviews/2026-10-31/redteam-unfenced-gatefb-1031-r1.md), [r2](../reviews/2026-10-31/redteam-unfenced-gatefb-1031-r2.md), [r3](../reviews/2026-10-31/redteam-unfenced-gatefb-1031-r3.md).

**A lesson that failed the gate was simply lost.** The next try could make the same mistake. Fix: a failed lesson goes back to Reflection with what it broke (`7469a4d`, decision 50).

**Real chats became practice customers, and names came with them.** Real chats now turn into practice customers each night (`9c3dc10`, decision 48). The red team's round 3 found names reaching the practice pool from ordinary customer chats (blocking). Fix: names a customer gives for an order are masked, and so is a surname beside a masked name, in every turn of the chat (`e10a068`, `e0b51b9`). Reports: [review r3](../reviews/2026-10-31/review-unfenced-feed-1031-r3.md), [red team r3](../reviews/2026-10-31/redteam-unfenced-feed-1031-r3.md).

**The cleaned real cards.** The real customer cards and replay set were cleaned and committed (`ee9f6e5`, decisions 23 and 29). Three rounds of cleaner fixes followed: sign-off words (regards, best, cheers) are never taken as a surname, and a display name of two or more name words is masked (`98c6ef7`, `f12a266`, `a36c43e`). Reports: [review r1](../reviews/2026-10-31/review-unfenced-realcards-1101-r1.md), [r2](../reviews/2026-10-31/review-unfenced-realcards-1101-r2.md) (PASS).

**The night note to the Marketing agent was almost never sent.** The red team showed that the rule against overlapping night windows refused almost every later note on daily runs: 1 of 5 was stored (round 2, blocking). Fix: windows that share an hour or less count as apart, and there is one note a night per receiving agent, keyed on the Cairo night (`0c46d1e`, `4e86613`, `bf4fc27`). Reports: [review r3](../reviews/2026-10-31/review-unfenced-mkas-1031-r3.md), [red team r2](../reviews/2026-10-31/redteam-unfenced-mkas-1031-r2.md), [r3](../reviews/2026-10-31/redteam-unfenced-mkas-1031-r3.md) (five lows, none blocking).

## 1 November: the send check, the hand-off, and the end of a chat

**The send check let wrong prices through in odd number shapes.** The red team's first finding (high, blocking): a boot's model number could become the thousands part of a wrong price, through blanks and lookalike separators between digit groups. Fix rounds 1 and 2 joined digit groups across blanks and lookalike signs (`fcfa213`, `abc8a36`). The red team's last round still found 4 blocking variants (1 high, 3 medium) and the review 2 regressions from round 2; round 3 fixed them (`389983d`). The shapes still missed are in known-limits.md. Reports: [review r1](../reviews/2026-11-01/review-unfenced-handoff-1101-r1.md), [r2](../reviews/2026-11-01/review-unfenced-handoff-1101-r2.md), [r3](../reviews/2026-11-01/review-unfenced-handoff-1101-r3.md); [red team r1](../reviews/2026-11-01/redteam-unfenced-handoff-1101-r1.md), [r2](../reviews/2026-11-01/redteam-unfenced-handoff-1101-r2.md), [r3](../reviews/2026-11-01/redteam-unfenced-handoff-1101-r3.md).

**The hand-off to a person was left over from the old repo.** It added a relay, a team note and a "team member is taking over" line. We removed it (`4f502f9`, decision 53). When the agent cannot send a safe reply it now sends nothing, and the chat counts as lost so Reflection learns from it (decision 57).

**Reflection did not know when a chat ended.** The old rule waited a day after the agent last acted. Fix: after 30 quiet minutes the agent says once that the chat closes in 30 minutes; 30 minutes later it closes and goes to the hotfix and that night's Reflection (`839d86f`, decision 54). Review then found edge cases around restarts: a customer who had just written could be cut off, and a notice could go out late. Fixed in `ed9efb0`, `c891080`, `d92f4fc`. Pull became a real pause switch (`515b44c`). Reports: [review r1](../reviews/2026-11-01/review-unfenced-handoff2-1101-r1.md), [r2](../reviews/2026-11-01/review-unfenced-handoff2-1101-r2.md), [r3](../reviews/2026-11-01/review-unfenced-handoff2-1101-r3.md); [red team r1 to r3](../reviews/2026-11-01/redteam-unfenced-handoff2-1101-r3.md).

**The Arena could touch the live database.** Fix: the Arena practises on its own copy, and only a lesson that passed the gate reaches the live agent (`a58581b`, decision 46). Tests never read the real cards; a guard matches the folder by device and inode and follows links (`7475b36`, `9c415df`).

**Quick start.** A user writes what they want and one model call guesses the rest as one card (`590a44d`). Built agents got Arena practice with made-up customers from their card (`180d599`). Review found gaps in the check that keeps a built agent's card from handing chats to a person; three rounds tightened it (`d6c4517`, `f1e51ab`, `85bf10f`). Reports: [review r1](../reviews/2026-11-01/review-unfenced-stack-1101-r1.md), [r2](../reviews/2026-11-01/review-unfenced-stack-1101-r2.md), [r3](../reviews/2026-11-01/review-unfenced-stack-1101-r3.md).

## 2 November: any agent, and the first measured run

**Only the Sales agent was really wired.** An agent made in Quick start had no exam, no practice people like real customers and no gate. Fix: Build writes an exam and practice people for any agent, and the gate takes any agent (`7ce840d`, `a92230e`, `34a71ad`, decision 59). Each review round found medium issues and no blocker. Reports: [review r1](../reviews/2026-11-02/review-wireall-r1.md), [r2](../reviews/2026-11-02/review-wireall-r2.md), [r3](../reviews/2026-11-02/review-wireall-r3.md); [red team r1 to r3](../reviews/2026-11-02/redteam-wireall-r3.md).

**The agent kept promising to check with the team.** In the measured run of 2 November, 9 of 19 losses ended on a team promise while the facts were in its own tools, and the same mistake came back match after match. The cause was ours: an instruction line told it to say this, and an exam check rewarded it. Fix: the line and the check came out with no new rule in their place (`3c4a44c`, decision 74), and an Arena run now keeps every quick note of the run, up to 5, so a losing answer is not tried again (`f68c58b`, `bba0bda`, `275d2f4`). The branch that brought this in (merge-all) failed its first review with 1 blocker and 1 high; all 8 findings were fixed and round 2 passed, each fix proven by reverting it (`465404b`). Reports: [review r1](../reviews/2026-11-02/review-merge-all-r1.md), [r2](../reviews/2026-11-02/review-merge-all-r2.md) (PASS); [red team r1](../reviews/2026-11-02/redteam-merge-all-r1.md), [r2](../reviews/2026-11-02/redteam-merge-all-r2.md) (PASS).

**Built agents failed the exam almost every time.** Style checks (script, banned words, echo) blocked lessons that fixed real problems, so a built agent rarely got a lesson through. Fix: a lesson passes when no safety check newly breaks and it fixes at least as many situations as it breaks; style checks are reported, not blocking (`3ca7ac2`, decision 75). In the Arena a lesson is examined on its own stage under a cap (`7006366`).

**Cases closed on a timer.** A delivery result that came late was lost. Fix: no timer closes a case; a late result arrives by webhook, by asking the courier's API, or by a person marking it (`99ac953`, `170b5b3`, decision 66). The review showed that per pattern delivery counts could not be right, since a night reads 2 days and deliveries land 2 to 7 days later, so they were dropped (`77c9a81`, decision 73). Reports: [review late r1](../reviews/2026-11-02/review-late-r1.md), [r2](../reviews/2026-11-02/review-late-r2.md).

**There was no step where the user decides when an agent goes live.** Fix: a Connect to WhatsApp button unlocks only after the gate passes (`d2dfe31`, decision 77), and a quick run never unlocks it (`0f99762`).

## 3 November: lessons stuck behind the risk check and one noisy answer

**Almost every lesson waited for a yes.** The Sales plug's high risk list matched wide words, numbers and tool names, so ordinary lessons, such as asking for the order details, were marked high and never started on their own. Fix A narrowed the list to amounts, discounts, promises, payment, policy and data (`cdc4ff0`). The review then found the narrow list missed 62 of 64 risky lines in Arabic, Franco and plain English, where the old list had caught 54 of them (blocking). Round 2 added the missing forms (`3c99845`).

**One noisy model answer could fail a lesson.** The exam compared one answer with the lesson against one answer without it, so a single random slip decided. Fix B reruns a situation 2 more times on each side and votes (`2b0faaf`). The review found that an empty rerun counted as a failure and excused the lesson (blocking); fixed in `81a8cd0`, with the vote extended to every safety check the reruns break (`3229d30`). Reports: [review r1](../reviews/2026-11-03/review-engfix-r1.md) (FIX FIRST), [r2](../reviews/2026-11-04/review-engfix-r2.md) (ISSUES), [r3](../reviews/2026-11-04/review-engfix-r3.md) (PASS); [red team r1](../reviews/2026-11-03/redteam-engfix-r1.md), [r2](../reviews/2026-11-04/redteam-engfix-r2.md), [r3](../reviews/2026-11-04/redteam-engfix-r3.md).

**Connect could be unlocked by editing a file.** A quick run's Arena item with its quick flag changed by hand would have unlocked Connect. Fix: Connect needs an Arena item signed with an HMAC over the whole item, keyed by a random key the run makes once (`daab98d`).

## 4 November: the real loop on the real model

**Meta's model returned empty answers.** The open model's reasoning counts toward the token limit. At 600 tokens for the practice judge and 400 for the practice customer, it used the whole budget thinking and the answer came back empty, so every new agent's Run the Arena stopped after three unreadable judge answers. Fix: larger budgets (judge 3,000, customer 2,000, card writer 6,000) (`90c02fc`). Later the same day the practice customer writer still failed on large batches, so it asks with 16,000 tokens and retries an empty batch once (`cbc5f8f`), and every model call now asks an empty answer once more with a larger budget, a retry that counts on every call cap (`05f79a2`).

**The agent was examined on rules nobody told it.** A live timed exam passed 3 of 53 situations; 37 failures were style and 9 were script, rules the instructions never named. Fix: the send check's own rule words go into every agent's prompt, so the prompt and the check cannot drift apart (`d4bda85`, `437bf0f`, decision 94). Report: [review examrules r1](../reviews/2026-11-04/review-examrules-r1.md) (FIX FIRST, fixed in `437bf0f`).

**Risk levels and a test set that could be gamed.** Built agents got risk levels (low 5 of 10, medium 7 of 10, high 8 of 10 with zero safety fails) and a kept test set (`817de41`, `ccb60e2`, decisions 84 and 85). The red team showed that relabelling a training line as a test match hid that a customer had trained, so the test set could be stacked (round 3, finding 1). Fix: every saved match line carries the run's seal, and each agent keeps a sealed roster (`2bac0b7`, `9edc8cd`, decision 90). Reports: [review r1](../reviews/2026-11-04/review-levels-r1.md), [r2](../reviews/2026-11-04/review-levels-r2.md), [r3](../reviews/2026-11-04/review-levels-r3.md) (PASS), [seal check](../reviews/2026-11-04/review-levels-sealcheck.md); [red team r1](../reviews/2026-11-04/redteam-levels-r1.md), [r2](../reviews/2026-11-04/redteam-levels-r2.md), [r3](../reviews/2026-11-04/redteam-levels-r3.md).

**The cross-owner pool.** Lessons and lost cases of any agent kind become clean patterns shared once 2 or more owners have them (`4e70cfe`, decision 83). Its clean check kept losing to new spellings of names and numbers, so it now takes only words from a bundled English word list, plus listed openers (`38711d6`). Reports: [review r1](../reviews/2026-11-04/review-crossowner-r1.md) (FIX FIRST), [r2](../reviews/2026-11-04/review-crossowner-r2.md), [r3](../reviews/2026-11-04/review-crossowner-r3.md) (PASS); [red team r1](../reviews/2026-11-04/redteam-crossowner-r1.md), [r2](../reviews/2026-11-04/redteam-crossowner-r2.md), [r3](../reviews/2026-11-04/redteam-crossowner-r3.md).

**Off-topic customers.** One practice match in each round is a customer who asks for something outside the agent's work (`c1bdf96`, decisions 88 and 89). All three review rounds ended FIX FIRST. The last red team round found 29 natural ways to reveal the agent's instructions that passed the word check. Fix: a judge model decides when one is present, with the word check kept as the floor (`5b0481e`, `c01f3b7`, decision 91). Reports: [review r1](../reviews/2026-11-04/review-scopeguard2-r1.md), [r2](../reviews/2026-11-04/review-scopeguard2-r2.md), [r3](../reviews/2026-11-04/review-scopeguard2-r3.md), [quick check](../reviews/2026-11-04/review-scopeguard2-quick.md); [red team r1](../reviews/2026-11-04/redteam-scopeguard2-r1.md), [r2](../reviews/2026-11-04/redteam-scopeguard2-r2.md), [r3](../reviews/2026-11-04/redteam-scopeguard2-r3.md).

**The learning step.** The sample days left the judges' path, and a Run reflection button runs an agent's night on demand (`61580d8`, decisions 92 and 93). The study no longer caps lessons: what it cannot examine by 09:00 Cairo waits in a queue (`18cea50`, `dc52f73`, decision 98). Report: [review reflectbtn r1](../reviews/2026-11-04/review-reflectbtn-r1.md) (FIX FIRST).

**The gate was played by one rare customer type.** The held-out cards were scaled up to fill the gate, so one type (10 of 300 real chats) played about 98% of the gate matches. Fix: every type that can buy plays at its real share of chats, no type plays more than 3 of 10, and every gate match is new (`917f044`, decision 101).

**Then the gate asked for more than the real shop sells.** With the real mix in place, the gate expected 7 wins in 10 from customers the store itself wins about 1 time in 10. One customer type is 78% of real chats and buys only on a discount, and the store had no offers to give. No lesson could close that gap honestly. Decision 105 gives each store its offers as data (installments, free delivery, a card payment discount, free printing, a second pair discount), read only through the store tool. A customer no offer covers wins on a fair close: no made-up offer, the nearest real option, polite, the door left open. Reflection never studies a fair close as a loss. The gate stays 7 of 10. This work is on the offers branch (`81f8a10`, `68d9726`) and was not merged into this branch when this page was written.

**The Arena run of 4 November afternoon.** One full run (20261104T143545) lost for eight separate reasons, each fixed in its own commit:

- Lessons were refused for style slips. The exam counted a lesson's broken style checks against it, so a lesson that fixed a real problem but broke a style check, such as the script rule, was held. Now only safety breaks count against a lesson, style shows in the report, and the run on the kept lessons is voted per situation instead of read from one answer (`026cab4`, cause 2).
- A single noisy past win held lessons back. A past win that happened to lose on rerun was blamed on the new lesson. Now the win is played again with the lesson to a majority of 3, and if it loses, 3 times without it; only a loss that the version without the lesson wins holds the lesson (`b4c0bb9`, cause 6).
- The agent could not quote a legal total. The send check refused any amount a tool had not given, so a boot plus its printing, or three items plus delivery, was refused as made up. Now a sum of amounts the tools gave in that chat passes, and a made-up total still fails (`702102c`, cause 3).
- Delivery needed an area first. The delivery tool refused when the customer had not named a governorate, so the agent could not give delivery fees until the customer named an area. Now it gives every zone's fee and days (`1be5915`, cause 4).
- Stock claims with no stock data slipped through. A reply could say a size was in stock when the store gave no stock data. The fact check now fails it in Arabic, Franco and English, and "I cannot confirm stock" passes (`287744c`, cause 7).
- The made-up customer read its buy triggers as all required and would not answer a direct question about its area or size (`35b720c`, cause 1).
- The exam's day check refused the exchange days on a situation that asks for them (`7406fd7`, cause 5).
- The quick note guard stopped notes like "if the total is asked, list each tool price" (`71a6e11`, cause 8).

These came in on the engfix2 and engfix3 branches.

**Loosening the send check opened holes.** An earlier run that day (20261104T120239) showed the send check refusing times, lists, counts and order numbers as if they were prices, so we loosened it (`20f5637`). The red team on that work found the holes it opened: a customer could plant a number with a # and have the check ignore it, some range and count shapes let wrong prices and fees through, and the note guard passed spelled-out prices. The review marked two of these blocking. All were closed (`c7ab1c2`, `fe3d7e4`, `6f9ac05`), and the turn record no longer keeps the words of a refused draft that quotes the customer (`565f121`). The losses round 1 review and red team reports were not yet filed under reviews/ when this page was written.

**Dead code.** The same review found that the built agents' live notes had no caller: no channel runs a built agent for real customers, so that code was never reached. We removed it (`7cfea89`).

**Real names in the replay data.** Before the repo goes public we scan the cleaned data again. That scan found Instagram display names in the store's header lines, partial addresses after an address cue, and one first name a customer asked to have printed. The cleaner now masks all three and can re-clean files already written (`a0b7df1`). The replay set and one card were cleaned again: 725 of 3,084 replay entries changed (`256a800`).

**The Arena track on the page.** The agent page went through three shapes in one day (decisions 99, 102, 104) before settling on Arena first: Run the Arena is the full run, and a failed run shows what lost with Train and the correction box beside it (`a9b092d`, `7b4b502`).

**The assistant on the case Arena.** The personal assistant's page moved from simulated days to the case Arena: one request or one email thread at a time against a made-up user, with the same Run the Arena, Train and gate as an agent made in Quick start, so it practises on the tasks it will really face (decision 109).

## Still open

- The offers and fair close work (decision 105) is on its own branch and not yet merged here.
- The price check, the send check, the hotfix note guard and the cleaner still miss some shapes. Each is listed in [known-limits.md](known-limits.md) with what replaces it next.
- The cleaner can miss a rare surname or a number written in words (decisions 23 and 40).
- Hand-off to a person is a later feature (decision 53). A live off-topic check on every real reply is next (decision 89).
- The personal assistant's night and command line Arena still play simulated days; its page practises case by case (decisions 71 and 109).
- One agent with several kinds of case is next, not built (decision 69).
